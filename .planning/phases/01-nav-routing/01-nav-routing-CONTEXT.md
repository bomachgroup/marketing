# Phase 01 — Nav Routing — Planning Context

**Phase goal:** Wire the sidebar (and all in-screen `goSc`-style navigation) to TanStack Router routes so clicking a nav item changes the URL and renders the correct screen — mirroring the HTML reference's `goSc(id)` / `renderNav(role)` / `setRole(role)` behavior.

**Source:** User-provided phase spec (verified against the codebase on 2026-07-31). No ROADMAP.md exists yet; requirement IDs below are derived from the user's gaps and referenced in the plan frontmatter.

---

## Verified facts (codebase as of planning time)

- Routes exist 1:1 for 37 screens in `src/routes/*.tsx` (TanStack Router v1 file-based, `routeTree.gen.ts` auto-generated by the Vite plugin). `src/routes/index.tsx` redirects `/` → `/dashboard`. `src/routes/leads-detail.tsx` is a **static** route reading `id` from `validateSearch`.
- `src/routes/__root.tsx` → `AppShell` → `Sidebar` + `TopHeader` + `<Outlet />`. `AppShell` shows `LoginScreen` when `!isLoggedIn`.
- **`curSc` consumers (grep-verified, complete list):** `TopHeader.tsx` (search), `Sidebar.tsx` (active state + click), `LoginScreen.tsx` (login), `WorkdeskPage.tsx` (destructured but **never used** — dead), `StoreContext.tsx` (definition). `AppShell` does **NOT** use `curSc` (correction to the spec).
- **`navigate({ to })` call sites (grep-verified):** LeadsDetailPage (→ `/pipeline` ✓), NewLeadPage (→ `/pipeline` ✓), CampaignsPage (→ `/campaigns` ✓), AnalyticsPage (→ `/dashboard` ✓), DashboardPage (→ `/pipeline`, `/new-lead` ✓), PipelinePage line 96 (→ `/leads/$id` ✗ **broken — no such route**). MediaLibraryPage / TeamDirectoryPage / SupportPage / DesignPage declare `useNavigate()` but never call it (pre-existing dead imports — **not** in scope).
- **`npx tsc --noEmit` passes today** (TS ~6.0.2). Notably, `navigate({ to: \`/leads/$id\` })` compiles — route-typed `to` is NOT enforced in this setup, so dynamic path strings (`'/' + screen`) are type-safe in practice.
- **TypeScript config:** `strictNullChecks: true`, `noUnusedLocals: true`, `verbatimModuleSyntax: true`, `noEmit: true` (tsconfig.app.json). Keep all of these.
- **Store:** `StoreContext` persists to `localStorage` under `bomachOS_v3_react`. `activeJournalLead` / `setActiveJournalLead` exist but have **zero consumers** (ready for the search→journal wiring). `opsState.partnerTasks` holds 3 seeded partner tasks (PT-01..PT-03) — data for the Partner Portal screen exists.
- **ROLES** (defaults.ts) keys: `ceo, mgr, coord, bizdev, digital, content, creator, graphic, sales, care, partner, analyst, realtor, influencer`. Every nav item `s` maps 1:1 to a route EXCEPT **`partner-portal`** (no route file, no screen component — HTML reference has a full `sc-partner-portal` screen: "Influencer & External Partner Work Portal").
- **HTML titles** (four maps merged; used for `document.title`): see Plan 01 Task 1 — all 37 nav screens have titles.
- **Role first nav screens** (for `setRole`-style navigation): ceo→workdesk, mgr→workdesk, coord→**daily-execution**, bizdev→workdesk, digital→workdesk, content→workdesk, creator→content-studio, graphic→workdesk, sales→workdesk, care→workdesk, partner→workdesk, analyst→revenue-command, realtor→workdesk, influencer→workdesk.
- **HTML `setRole(role)`:** `renderNav(role)` then `goSc(r.nav[0].items[0].s)` — role switch lands on the role's FIRST nav item. `goSc(id)`: toggle screen, `curSc = id`, set page title (`titles[id] || id`), toggle active nav item, close mobile sidebar.
- Not a git repo (no commit step; the executor should not attempt git operations).

## Decisions (locked for the executor)

| ID | Decision | Status |
|----|----------|--------|
| D-01 | **Router URL becomes the single source of truth for the current screen.** `curSc`/`setCurSc` are **fully removed** from `StoreContext` (not kept in sync). Rationale: 4 small consumers, all replaced by router logic this phase; keeping it would create a second persisted source of truth that drifts (stale localStorage `curSc` survives reload, back/forward breaks). Removal is atomic within Plan 02. | LOCKED |
| D-02 | **Sidebar active highlight derives from `useLocation().pathname`** (exact equality with `'/' + item.s`). No item highlighted for `/leads-detail` (matches HTML: `lead-detail` is not a nav item). | LOCKED |
| D-03 | **Role-switch navigation** (HTML `setRole`): shared helper `roleFirstScreen(roleKey)` in `src/navigation.ts`; wired into the Sidebar role `<select>` (Plan 01) and the DashboardPage role `<select>` (Plan 02). **Correction to spec:** the React `TopHeader` has NO role-switch menu (only "Signed in as" + Sign out) — matches the HTML top bar (badge only). No change needed; adding role items to the header menu is out of scope (flag for the user if wanted). | LOCKED |
| D-04 | **Pipeline card click** → `navigate({ to: '/leads-detail', search: { id: l.id } })` (fix the broken `/leads/$id`). | LOCKED |
| D-05 | **TopHeader search result click** → `setActiveJournalLead(lead)` + `navigate({ to: '/leads-detail', search: { id } })`. `LeadJournalPage` consumes `activeJournalLead` as its initial `selectedLead` and keeps it in sync on manual select. | LOCKED |
| D-06 | **Login** → `login(selectedRole)` then navigate to `'/' + roleFirstScreen(selectedRole)` (mirrors HTML `setRole` landing on the role's first nav item — e.g. coord lands on `/daily-execution`, not `/dashboard`). | LOCKED |
| D-07 | **`document.title` per route**: single effect in `AppShell` watching `useLocation().pathname`, using the merged HTML `SCREEN_TITLES` map (fallback: raw path segment). One place, mirrors `goSc`'s title update. | LOCKED |
| D-08 | **`partner-portal`** — the HTML defines a full screen (Influencer & External Partner Work Portal: KPIs, task list, assign task, submit report) and the data exists (`opsState.partnerTasks`). **Default: build a new `PartnerPortalPage` + `/partner-portal` route** (Plan 03, standalone so it can be vetoed). **OPEN for user veto** — reply "drop plan 03" to skip (or "remap to realtor-portal" to avoid the new screen). | OPEN (default: build) |
| D-09 | **In-screen navigation audit** — grep-verified complete: only Pipeline is broken. Dead `useNavigate` imports in MediaLibraryPage/TeamDirectoryPage/SupportPage/DesignPage are pre-existing and NOT touched (out of scope). | LOCKED |
| D-10 | **No new dependencies.** No test framework exists in the project; this phase is router/glue wiring — verification is `tsc --noEmit` + `vite build` + agent-browser. Dynamic path strings compile (see verified facts). If a future TS upgrade narrows `navigate({ to })`, use the `screenPath()` helper result with a cast — not needed today. | LOCKED |

## Out of scope (explicitly NOT planned)

- `src/App.tsx` (unused Vite template file, not imported by `main.tsx`).
